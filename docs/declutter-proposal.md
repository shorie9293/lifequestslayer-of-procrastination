## 二、根本原因（3つ）

1. **単一画面への集積** — 寄合所の溢れメニュー14項目は「クエスト管理」の全機能が1つの `PopupMenuButton` に詰められた結果。階層が無いので、初見では全部が同列に見える。
2. **関心の混在** — 寺院に「転職・技の解放」（遊び）と「CSV書き出し・バックアップ・復元」（管理）が同居。設定ハブの「自動バックアップ」と機能が重複している。
3. **重複入口** — `HabitCalendarScreen` と `PomodoroTimerScreen` はそれぞれ2箇所（溢れメニュー＋職業スキルプルダウン）から到達。同じ行き先が別名で2回出る。

---

## 三、提案

### 提案A: 情報アーキテクチャを「3層」に分ける

全38画面を **日常 / 週次 / 管理** の3層へ機械的に割り当てる。層が決まれば置き場所が一意に決まり、以後の追加も迷わない。

- **第1層（毎日・タブ直下）**: 修練場（戦闘）／寄合所（今日のクエスト）
- **第2層（週次・タブ内サブハブ1枚）**: 習慣カレンダー・連続記録・見積精度・テンプレート・プロジェクト・ポモドーロ・振り返りの杜
- **第3層（管理・設定ハブ）**: 通知/静穏時間・カレンダー入出力・Google ToDo・現世間連携・バックアップ・アプリロック・文字サイズ・動きを減らす・アカウント削除・ヘルプ・チュートリアル再開

→ 寄合所の溢れメニューは **14 → 5**（新規作成系＋第2層ハブ1枚＋ヘルプ＋設定）。第2層ハブは `QuestManagementScreen` 1枚で、そこに7項目を並べる。

### 提案B: 「1機能1入口」原則

同じ画面へ2箇所から入れる状態を禁止する（例外は「文脈起動＝その場の作業から直接開く」場合のみで、理由を `docs/decisions.md` に1行残す）。
実測の是正対象:
- `HabitCalendarScreen`（2箇所）→ 第2層ハブへ一本化
- `PomodoroTimerScreen`（2箇所）→ 同上

### 提案C: 段階開示を「画面単位」へ拡張

既に `JobSkill` の未解放グレーアウト機構（`ProjectListScreen` / `PomodoroTimerScreen` 等が職業Lvで解錠）が動いている。**この機構を画面の表示可否にも使い、Lv不足の機能は入口自体を出さない**。新規利用者の初期画面は「修練場・寄合所・クエスト作成・設定」だけになる。

### 提案D: 画面名に機能の説明を必須化

「寺院」「門前町」は世界観として正しいが、初見で中身が分からない。サブタイトル1行（例: 寺院＝「転職と技の解放」／門前町＝「建物を育てる」）を全画面の AppBar 直下に固定する。名称は変えずに説明を足すので、世界観は壊さない。

### 提案E: 削るのではなく「測ってから削る」

どの入口が実際に使われているかを今は誰も知らない。**画面遷移カウンタ（Hive 1キー・ローカルのみ・送信なし）を2週間回し、0回の入口から順に畳む。** 証拠なき削除は「便利だった機能を消した」事故になる。
